# The bus

Watcher's side of the CannObserv bus: who operates the broker, which streams watcher publishes and consumes, how each is retained, and the client's connection policy. The client underneath it: [BUS-CONNECTION-POLICY.md](BUS-CONNECTION-POLICY.md).

## Redis and the bus

**Redis and the bus (archiver#109, #245).** The broker is its own VM (tailnet node `broker`), operated from CannObserv/broker since archiver#193 D6 — its tuning, health probe and stream inventory live there, and Archiver, like Watcher, is a client; Archiver still owns the `info.changes` fact stream. **Watcher publishes on five streams and consumes three.** Publish: `content.fetch` (commands, #241), `content.process` (commands, #325), `content.fetch-policy` (#245), `content.revisions` (`source_revision_observed` — the Archiver HTTP write path retired in #253), and `info.watch-status` (#264 — see below). Consume: `content.blobs` and `content.derived` (fact streams, a consumer group each) and `info.registry` (config/state stream, **groupless**). The politeness producer is the `content.fetch-policy` producer (#245; `src/core/fetch_policy.py` + the `publish_fetch_policy` periodic task) — Watcher's half of the cluster politeness split (*mechanism to Replicator, policy to the issuer, config over the bus*; normative: `docs/contracts/replicator-boundaries.md` in the Replicator repo). It publishes each `Domain.min_interval` (the retired limiter's `current_interval` backoff state was inert since #241 and dropped in #272) as a `FetchPolicyState` per host, full-set-republished every 5 minutes **including tombstones** (`fetch_policy_tombstones` table, written on domain delete, cleared on re-create) so a consumer's boot replay never depends on broker retention. Connection via `WATCHER_BUS_REDIS_URL` (unset → loud skip, Replicator falls back to its conservative default; `scripts/dev_server.sh` clears an inherited value unless `WATCHER_DEV_BUS_REDIS_URL` opts into a scratch bus). **A URL is configuration, not permission (#262).** `WATCHER_BUS_REDIS_URL` lives in `/etc/watcher/.env`, so anything that sources it — an agent shell, a one-off script, a `python -c`, a REPL — inherits the production broker; before the gate, importing a producer in one of those was enough to reach the live streams, and it happened (the #253 cutover published a fabricated `source_revision_observed` frame onto production `content.revisions`, inert only because the fixture's `info_source_id` was fake). Archiver's "a stray producer is merely noisy" reasoning (archiver#139) does **not** transfer: a stray `content.fetch` makes Replicator issue real origin requests against government portals under Watcher's pinned User-Agent; `content.fetch-policy` is LWW per host, so a dev database's numbers become cluster-wide politeness instruction until the next full-set republish (and a domain the dev DB lacks is not tombstoned — the stale frame simply stands); `content.revisions` writes into *Archiver's* registry, which a dev DB seeded from production would fill with real-looking rows. So `bus_client_from_env()` additionally requires **`WATCHER_BUS_ENABLED=1`** — one flag gating publish *and* consume, set only by `deploy/watcher.service` and by `dev_server.sh`'s scratch-bus branch, never by an env file (the `WATCHER_ALLOW_PRODUCTION_DB` precedent, #233). Failing closed and *silently* would only trade hazards, so the pairing that is always a mistake in either direction — URL present, flag absent — raises `BusNotEnabled` from the lifespan and the process refuses to start. The assertion lives in the lifespan (`src/api/main.py`), deliberately **not** at import of `src/core/bus.py`: an import-time check would abort alembic, everything under `scripts/`, and the tooling used to deploy the fix. API domain routes defer an immediate republish; **dashboard routes deliberately don't** (they must not import `src.workers.*` — `tests/dashboard/test_import_decoupling.py`) and ride the periodic tick. Watcher joins two single-member consumer groups — `watcher.blobs` (#241) and `watcher.derived` (#325) — and all async work still stays on Procrastinate over Postgres (`PsycopgConnector`); the bus carries facts and commands, never jobs. **The taxonomy is enforced, not just followed** — `tests/test_bus_stream_kinds.py` reads `src/` **and `scripts/`** (the #262 gate exists because a one-off script can reach the broker too) and branches on co-core's `stream_kind`: a grouped `AsyncBusConsumer` may not target a config/state stream, an `AsyncBusTailReader` may only target one, every binding of a consumer group must be a `group_name` call rather than a literal — *every* binding, since one derived assignment says nothing about a later rebinding, and every config/state publish must carry a `maxlen` that came from a **bounded** resolver (its producer republishes the full set, so the trim is a contract property and not an operator's `XTRIM` — and a cap of `0` is worse than none, trimming the stream to one entry so a boot replay returns a partial set no consumer can distinguish from a complete one). **Bounded is not the same as bounded *usefully* (#292).** A groupless consumer replays the whole stream from `0-0` at every boot, so the cap has to be sized against the *set* rather than against the broker's comfort: a flat `50_000` against a three-host policy set is ~34 days of republish history, and `content.fetch-policy` duly reached 29,770 entries for a 950-second replicator boot replay (replicator#85) while `info.watch-status` reached 30,452 for four items. Both defaults are now `500`, floored at `RETAINED_FULL_SETS` (10) copies of the batch being published — so a corpus that outgrows the constant raises the cap instead of being trimmed below one full set, which is the same partial-replay failure as a cap of `0` reached from the other side. No `XTRIM` is needed to collect the existing backlog: `MAXLEN ~` drops whole macro nodes and caps each call at 100 of them, so a 29,770-entry stream falls 10,000 per `XADD` and the first full-set republish clears it (measured on redis 7.0.15: 29,770 → 19,771 → … → 574 after four publishes; approximate trimming settles *above* the cap, never below — production confirmed it on the 02:25 UTC 2026-09-10 tick, 29,785 → 512 and 30,456 → 500 in one republish). The set of streams Watcher touches is pinned too, so adding a ninth fails here rather than quietly falsifying the *five published, three consumed* count above. Each rule was mutation-checked against a deliberately broken call site, and each asserts it found call sites so a class rename fails loudly instead of passing vacuously. **The group name is derived, never hand-written (#285, cannobserv#384):** `group_name(CONTENT_BLOBS, "watcher")` — `<service>.<stream-suffix>`, with no `purpose` segment because Watcher runs exactly one group on the stream. The helper is the contract rather than the prose: all five cluster groups diverged from the old written-only convention, because a rule with no artifact loses to whatever is typed at the call site, and `group_name` additionally raises on a config/state topic that must never grow a group. **`info.registry` is the third stream kind and behaves differently (#254).** A config/state stream is broadcast like a fact but last-write-wins per key, so its consumer joins **no** group: it replays from `0-0` with `AsyncBusTailReader` at every boot and then tails. Reading from `$` is the mistake that fails silently — a booting worker sees nothing, indistinguishable from a worker whose registry is genuinely empty — and the driver offers no way to spell it. There is **no DLQ**: an undecodable frame is logged and `seek`-ed past (there is no ack to skip one with), and the producer's periodic snapshot supersedes whatever was dropped. Ordering comes from `generation`, not arrival: apply iff `generation >` the stored value, because the producer's outbox drain reorders under retry. See `src/workers/registry_reconcile.py`. **`info.watch-status` is the registry channel's return leg (#264, contract cannobserv#321): Watcher is the producer.** Same config/state posture in the opposite direction — broadcast LWW per `info_item_id`, no group, no DLQ, no outbox (a dropped frame is corrected by the next full set, which is why the republish period is the recovery bound; `WATCHER_WATCH_STATUS_REPUBLISH_CRON`, default 5 minutes). Payload is **levels, never edges** — `applied_generation` (0 = nothing newer than generation 0 applied — a never-mutated InfoItem legitimately announces at 0, so the sentinel collapses "never reconciled" with "reconciled at 0"; benign under apply-iff-greater), `applied_active` (the conjunction the scheduler actually gates on), `applied_interval` (the resolved cadence **after** the throttle floor, so cadence-only drift is visible), `health` (`ok`/`error`/`unknown`), `last_attempt_at`/`last_observed_at`, and tombstones from `revoked_info_items`. Publishes fire on reconcile (post-commit — the publisher only ever reads committed rows, so `applied_generation` cannot travel early), on health/active/floor transitions, and on the periodic tick — **never per fetch cycle**; a steadily-healthy item costs one frame per period regardless of fetch rate. Archiver tails it into its `watch_status` table and renders the watched-item panel and announced-vs-applied drift detector from it (archiver#151). **It must never become an ack path**: nothing in Watcher blocks on Archiver reading it. See `src/core/watch_status.py` + `src/workers/watch_status.py`. Bus ownership design of record: `docs/plans/2026-07-29-redis-bus-ownership-design.md` in the Archiver repo ([on GitHub](https://github.com/CannObserv/archiver/blob/main/docs/plans/2026-07-29-redis-bus-ownership-design.md)).

**Retention is sized against the set (#292), and mirrored on the broker (#319).** `tests/test_bus_stream_kinds.py` fails a config/state publish missing `maxlen` *or* `floor=`, and fails a retune of any mirrored number — the broker's probe thresholds are computed from copies, so the fix is cross-repo. The env overrides move the same numbers unseen (next paragraph).

**The retention numbers are mirrored on the broker node (#319).** `broker:src/broker/bus_health.py` holds copies of `RETAINED_FULL_SETS` and both `DEFAULT_*_STREAM_MAXLEN`, and since CannObserv/broker#44 its `FullSetFloor` *computes* each LWW stream's length threshold from them rather than only displaying them; the stream-age threshold is derived from the `*/5` republish period at 3x. So retuning any of the three here alone makes a live threshold there wrong in silence — early-warning if raised, quiet over a real backlog if lowered, the direction CannObserv/broker#40 was filed about. Each constant carries a comment naming its broker counterpart and `tests/test_bus_stream_kinds.py` pins all five, including that the watch-status periodic still *derives* its cron rather than carrying a literal. What nothing pins: the three environment overrides — `WATCHER_FETCH_POLICY_STREAM_MAXLEN`, `WATCHER_WATCH_STATUS_STREAM_MAXLEN`, `WATCHER_WATCH_STATUS_REPUBLISH_CRON` — which move the same numbers at deploy time with nothing in either repo's history to show for it. The set size is deliberately *not* mirrored: it changes with no edit anywhere, so the probe reads it off the stream span, which assumes one republish per period (CannObserv/broker#51).

**No retention on `content.fetch`, `content.process` (#325) or `content.revisions`, by decision (#327).** `maxmemory` is their only bound, as archiver#267 and replicator#119 chose (1,369 and 381 entries on 2026-09-24, ~29 and ~8.5/day). Watcher issues no `XTRIM`/`XDEL` (#317; CannObserv/broker#41 withdraws the grant) and `tests/test_bus_stream_kinds.py` fails a `maxlen` on either publish or any trim call. **Triggers**, checked by hand: `XLEN` past 10k on either, a CannObserv/broker#61 finding naming either, or issuing at production scale. **Then** file the grant on broker naming #327, and:
- **`content.fetch`:** `XDEL` by id once the row is terminal, `expired` included — an entry still pending in `replicator.fetch` is then dropped silently, cancelling a command the reaper already replaced. `XDEL` cannot cap, so broker's ACL keeps "never capped". Needs `+xdel ~content.fetch` and a column for the `XADD` entry id, which `publish_fetch_command` discards; best-effort, since a timed-out `XADD` the broker applied is republished under the same `command_id`.
- **`content.revisions`:** `XTRIM MINID` below every group's settled position (min of last-delivered and lowest pending). Needs `+xtrim` and `+xinfo|groups`; the code must refuse `MAXLEN`. A late-joining consumer gets no history — it backfills from Archiver, the system of record — so there is no floor beyond the groups.

## Bus connection policy

**The client carries an explicit connection policy (#287).** `socket_timeout` has a **floor**, not a ceiling — derived from `src/core/read_windows.py`, never transcribed; retries are an explicit **zero**, because a redis-py retry re-sends the command and a duplicated `content.fetch` is a duplicated origin request; and a detached startup `PING` exists because `from_url` is lazy, so a partition would otherwise present exactly as an idle cluster. Every value, the three measurements behind them, the redaction rules for the credential broker#1 D3 adds, and why the consumer loops need no error classification of their own: **[docs/BUS-CONNECTION-POLICY.md](BUS-CONNECTION-POLICY.md)**.
